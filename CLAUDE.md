# CLAUDE.md

Jekyll source for flannaghan.com. See `README.md` for the full tour — build
requirements, repo layout, and how the cycling route plugin works.

## Commands

- `jekyll serve` — preview on localhost:4000.
- `./build_and_publish.sh` — clean, build, and rsync `_site/` to the `lightsail`
  host. This publishes to the live site.

Publishing is outward-facing: ask before running it unless the user has already
asked for it.

## Things that are easy to get wrong

**The rsync has no `--delete`.** Deleting a file here does not delete it from
the server — it keeps serving at its old URL indefinitely. When you remove or
rename a page, also remove the old path on the server over ssh, and verify with
`curl -o /dev/null -w '%{http_code}'` that it 404s.

**Anything in `_site` is served publicly at the site root.** If you add a file
to the top level of the repo, decide whether it needs to go in the `exclude`
list in `_config.yml`. Deploy scripts, notes, and data files should not be
published. Renaming an excluded file silently un-excludes it, so update both.

**The site 301s `/foo.html` to `/foo`.** That is nginx stripping the extension,
not an error. Follow redirects (`curl -L`) when checking whether a page works.

**Don't hand-edit `_site/`.** It is regenerated by `jekyll clean` on every
publish. Edit the source and rebuild.

## Conventions

- Posts go in `_posts/` as `YYYY-MM-DD-slug.md` or `.html`. Tag a post
  `tool` to have it listed on the Tools page.
- Interactive tools are self-contained: markup and JavaScript live inline in the
  post itself, with shared libraries vendored under `js/` and `css/`.
- Commit messages are short and sentence-case ("Premium bond update").

## Skills

- `update-premium-bonds` — refreshing the Premium Bond Calculator with the
  latest NS&I rate, odds and prize pot. Use it rather than editing that post
  by hand; it covers the verification step against NS&I's published table.
